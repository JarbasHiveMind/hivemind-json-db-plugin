# AGENTS.md — `hivemind-json-db-plugin`

Guidance for AI coding agents (and humans) working in this repository. Read it
fully before making changes. It encodes conventions that are not obvious from the
code and that, if ignored, produce work that will be rejected.

## Repo

JSON-file database backend for HiveMind-core: it implements the
`hivemind-plugin-manager` `AbstractDB` contract (`JsonDB`) on top of
`json_database`'s `JsonStorageXDG` / `EncryptedJsonStorageXDG`, storing every
client record (API keys, crypto keys, ACL fields, metadata) as a single JSON
file on disk. It registers under the `hivemind.database` entry-point group
and is loaded by `hivemind-core` when `server.json` sets `database.module` to
this name — it is the default, zero-infrastructure database for development
and small single-host hubs. Part of the
[HiveMind](https://github.com/JarbasHiveMind) ecosystem — a protocol for
connecting satellite devices to a hub running
[OpenVoiceOS](https://github.com/OpenVoiceOS). Related repos:
[HiveMind-core](https://github.com/JarbasHiveMind/HiveMind-core) (the hub),
[hivemind-plugin-manager](https://github.com/JarbasHiveMind/hivemind-plugin-manager)
(defines `AbstractDB`/`Client`), [json_database](https://github.com/TigreGotico/json_database)
(the underlying storage library).

## Layout / build / test

- Package module: `hivemind_json_database/` (single `__init__.py` with the
  `JsonDB` dataclass, plus `version.py`). Tests live in `tests/` (unit tests
  in `tests/test_jsondb.py`, an end-to-end migration test in
  `tests/e2e/test_policy_migration_e2e.py`) — do not create a second test
  directory.
- Set up a throwaway environment inside your clone; never touch a shared venv:
  `python3 -m venv .venv && VIRTUAL_ENV=$PWD/.venv uv pip install -e ".[test]" --prerelease=allow`
- Run the unit suite in the foreground: `python3 -m pytest tests -q`
  (this also picks up the e2e test; CI runs the e2e file separately via the
  `integration` extra with `pytest tests/e2e/test_policy_migration_e2e.py -q`).
- `uv`, never `pip`. If latest prereleases fail to install or resolve, that is a
  bug to FIX at the source, not to work around with a pin downgrade.

## Tests

- Adversarial by default. A regression test must **fail before the fix and pass
  after** — prove it by reverting only the source (`git apply -R`, never
  `git stash` across worktrees) and watching the test flip.
- Tests must be mutation-proof: gutting the feature must fail the test. A test
  that only asserts a mock was called, without asserting the real behaviour, is
  weak — note it.
- Never skip a test because an optional dependency is missing.
- CI green is permission to review, not to merge. A non-trivial change gets an
  adversarial review before it lands.

## Repo-specific rules

- `JsonDB` sits on the auth hot path: `hivemind-core` calls `search_by_value`
  (including by `client_id`) to resolve API keys and ACL fields on every
  connection attempt. A lookup miss or a corrupt/unreadable JSON store must
  come back as "not found" (empty list / falsy), never raise past the caller
  and never synthesize or default a permissive record — deny, don't fail open.
- Every `Client` field written by `add_item` must round-trip through
  `commit()`/reload unchanged, including ACL lists (`intent_blacklist`,
  `skill_blacklist`, `allowed_types`, etc.) and the `metadata` dict — this is
  what `tests/test_jsondb.py`'s round-trip and snapshot tests exist to prove.
  `add_item` deep-copies the incoming `client.__dict__` specifically to avoid
  aliasing bugs where a caller's later mutation leaks into the stored record;
  preserve that when touching the method.
- The on-disk schema carries a version sentinel (`<name>.schema_version`,
  sibling to the JSON store) and `_maybe_migrate`/`migrate` apply schema
  changes idempotently and crash-safely — a re-run on a partially migrated
  store must converge to the same state. Any future schema change needs the
  same idempotency guarantee plus a dedicated migration test, mirroring
  `test_migrate_is_idempotent`.
- There is no in-memory cache to invalidate here (`sync()` just calls
  `self._db.reload()`); if a cache layer is ever added in front of this
  backend, every write path (`add_item`, `commit`, `migrate`) must invalidate
  it.
- `hivemind-plugin-manager`'s agent plugins (`opm.agents.chat`) are the modern
  replacement for solvers — do not add new solver-based code here.
